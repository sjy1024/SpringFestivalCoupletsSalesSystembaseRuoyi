# 春联小程序框架改造计划

## 一、需求分析与框架差异对比

### 1.1 核心业务需求

根据需求文档，春联小程序需要支持：

1. **普通商品购买**：从已有列表选购春联
2. **定制订单**：现场定制对联，显示订单排队和预估完成时间
3. **AI聊天**：与传统文化AI聊天，推荐对联
4. **订单管理**：管理员后台发送消息通知（短信/微信）
5. **后台管理**：商品管理、订单管理、库存管理、消息管理

### 1.2 现有框架（TDesign零售模版）vs 需求差异

| 功能模块 | TDesign模版 | 春联需求 | 改造难度 |
|---------|------------|---------|---------|
| 商品展示 | ✅ 完整 | ✅ 需要 | 低（只需对接API） |
| 购物车 | ✅ 完整 | ✅ 需要 | 低（简化即可） |
| 普通订单 | ✅ 完整 | ✅ 需要 | 低（对接API） |
| **定制订单** | ❌ 无 | ✅ **必须新增** | **高（全新功能）** |
| **订单排队** | ❌ 无 | ✅ **必须新增** | **中（需UI+逻辑）** |
| **AI聊天** | ❌ 无 | ✅ **必须新增** | **高（全新功能）** |
| 优惠券 | ✅ 有 | ❌ 不需要 | 低（删除即可） |
| 营销活动 | ✅ 有 | ❌ 不需要 | 低（删除即可） |
| 复杂售后 | ✅ 有 | ❌ 简化即可 | 低（简化） |

### 1.3 关键改造点

1. **数据源切换**：从 mock 数据 → 若依后端 API
2. **新增定制订单模块**：完整的定制流程页面
3. **新增AI聊天模块**：对话界面 + 推荐商品
4. **订单排队显示**：在订单详情页显示排队信息
5. **简化不需要的功能**：删除优惠券、营销活动等

## 三、详细开发计划（按优先级）

### 阶段一：基础数据对接（2-3天）⭐ 最高优先级

**目标**：让小程序能真实显示若依后端的商品和订单数据

#### 1.1 统一请求封装（0.5天）

**文件**：`services/_utils/request.js`

**功能**：
- 封装 `wx.request`，统一处理请求
- 配置后端API地址（BASE_URL）
- 统一错误处理和loading提示
- 自动携带设备ID（deviceId）

**关键代码结构**：
```javascript
// services/_utils/request.js
const BASE_URL = 'http://localhost:8080'; // 或你的服务器地址

export function request(options) {
  return new Promise((resolve, reject) => {
    // 获取设备ID
    const deviceId = wx.getStorageSync('deviceId') || generateDeviceId();
    
    wx.request({
      url: BASE_URL + options.url,
      method: options.method || 'GET',
      data: {
        ...options.data,
        deviceId: deviceId  // 自动携带设备ID
      },
      header: {
        'Content-Type': 'application/json',
        ...options.header
      },
      success: (res) => {
        if (res.data.code === 200) {
          resolve(res.data.data);
        } else {
          wx.showToast({ title: res.data.msg || '请求失败', icon: 'none' });
          reject(res.data);
        }
      },
      fail: reject
    });
  });
}
```

#### 1.2 设备ID管理（0.5天）

**文件**：`utils/deviceId.js`、`app.js`

**功能**：
- 小程序启动时生成唯一设备ID
- 持久化存储到本地
- 所有API请求自动携带

**实现**：
```javascript
// utils/deviceId.js
export function getDeviceId() {
  let deviceId = wx.getStorageSync('deviceId');
  if (!deviceId) {
    deviceId = 'device_' + Date.now() + '_' + Math.random().toString(36).substr(2, 9);
    wx.setStorageSync('deviceId', deviceId);
  }
  return deviceId;
}
```

#### 1.3 商品API对接（1天）

**改造文件**：
- `services/good/fetchGoodsList.js` → 调用 `/api/app/goods/list`
- `services/good/fetchGood.js` → 调用 `/api/app/goods/{id}`

**改造要点**：
- 将 `config.useMock` 改为 `false`
- 使用 `request.js` 发送真实请求
- 数据格式适配（后端返回的字段名可能与模版不同）

**示例**：
```javascript
// services/good/fetchGoodsList.js
import { request } from '../_utils/request';

export function fetchGoodsList(params) {
  return request({
    url: '/api/app/goods/list',
    method: 'GET',
    data: {
      goodsName: params.keyword,
      goodsType: params.type
    }
  }).then(res => {
    // 数据格式转换（适配前端组件）
    return res.map(item => ({
      spuId: item.goodsId,
      title: item.goodsName,
      thumb: item.coverImage,
      price: item.price,
      originPrice: item.originalPrice,
      desc: item.description
    }));
  });
}
```

## 五、技术难点和解决方案

### 5.1 数据格式适配

**问题**：后端返回的字段名可能与TDesign模版不同

**解决**：
- 在 `services` 层统一做数据转换
- 创建映射函数，将后端字段映射到前端需要的字段

### 5.2 订单排队算法

**问题**：如何计算排队位置和预估完成时间

**解决**：
- **排队位置**：查询 `status IN ('0','1')` 的定制订单数量
- **预估时间**：固定规则（如每个订单30分钟）或根据历史数据计算

### 5.3 AI接口调用

**问题**：AI API可能有调用限制或需要付费

**解决**：
- **演示阶段**：使用关键词匹配 + 预设模板
- **正式环境**：集成百度文心一言或阿里云通义千问（有免费额度）

### 5.4 设备ID管理

**问题**：如何在小程序中唯一标识用户

**解决**：
- 小程序启动时生成设备ID，存储到本地
- 所有需要用户标识的接口都携带 `deviceId`
- 后续可以升级为微信登录（获取openid）

## 七、注意事项

1. **API地址配置**：开发环境用 `localhost:8080`，生产环境需要配置实际域名
2. **跨域问题**：若依后端需要配置CORS，允许小程序域名访问
3. **数据格式**：注意后端返回的数据格式（RuoYi标准格式：`{code: 200, data: {...}, msg: "success"}`）
4. **错误处理**：所有API调用都要有错误处理和用户提示
5. **性能优化**：商品列表、订单列表需要分页加载
