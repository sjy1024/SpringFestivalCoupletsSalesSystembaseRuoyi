# 春联售卖系统 - 数据库设计说明

## 📋 设计原则

1. **遵循若依框架规范**
   - 使用标准字段：`create_by`, `create_time`, `update_by`, `update_time`, `remark`
   - 使用 `cl_` 前缀（春联系统）

2. **支持小程序端**
   - 使用 `device_id` 字段标识小程序用户（初版不登录）
   - 后续可扩展为关联 `sys_user` 表

3. **考虑后续扩展**
   - 预留字段和索引
   - 支持两种商品类型（普通商品 + 需要材质尺寸的商品）
   - 支持定制订单和排队功能

4. **符合ER图设计**
   - 用户 → 购物车 → 商品
   - 用户 → 订单
   - 用户 → 评价/收藏 → 商品
   - 管理员 → 订单管理
   - 管理员 → 公告

---

## 📊 表结构说明

### 1. **cl_goods（商品表）**
- **作用**：存储所有商品信息
- **特点**：
  - `goods_type` 区分普通商品和需要材质尺寸的商品
  - 支持多图片（JSON格式存储）
  - 包含评分字段
- **关联**：
  - 一对一到 `cl_goods_extend`（当 `goods_type=1` 时）

### 2. **cl_goods_extend（商品扩展表）**
- **作用**：存储需要材质尺寸的商品详细信息
- **特点**：
  - 只关联 `goods_type=1` 的商品
  - 存储材质、长度、宽度、尺寸等信息

### 3. **cl_cart（购物车表）**
- **作用**：存储用户的购物车信息
- **特点**：
  - 使用 `device_id` 标识用户（初版不登录）
  - 唯一索引 `(device_id, goods_id)` 防止重复添加
- **关联**：
  - 多对一到 `cl_goods`

### 4. **cl_order（订单表）**
- **作用**：存储订单主信息
- **特点**：
  - `order_type` 区分普通订单和定制订单
  - `status` 订单状态流转：待支付 → 已支付 → 制作中 → 已完成/已取消
  - 包含收货信息
- **关联**：
  - 一对多到 `cl_order_item`
  - 一对一可选到 `cl_custom_order`（当 `order_type=1` 时）

### 5. **cl_order_item（订单明细表）**
- **作用**：存储订单中的商品明细
- **特点**：
  - 存储商品快照（价格、名称），防止商品信息变更影响历史订单
- **关联**：
  - 多对一到 `cl_order`
  - 多对一到 `cl_goods`

### 6. **cl_custom_order（定制订单表）**
- **作用**：存储定制订单的详细信息
- **特点**：
  - 支持排队功能（`queue_no`, `queue_position`, `estimated_time`）
  - 存储定制内容和规格（JSON格式）
- **关联**：
  - 一对一到 `cl_order`（`order_type=1`）

### 7. **cl_goods_evaluation（商品评价表）**
- **作用**：存储用户对商品的评价
- **特点**：
  - 支持评分和文字评价
  - 支持评价图片
- **关联**：
  - 多对一到 `cl_goods`
  - 多对一到 `cl_order`（可选）

### 8. **cl_goods_favorite（商品收藏表）**
- **作用**：存储用户收藏的商品
- **特点**：
  - 唯一索引 `(device_id, goods_id)` 防止重复收藏
- **关联**：
  - 多对一到 `cl_goods`

### 9. **cl_ai_chat_log（AI对话记录表）**
- **作用**：存储AI聊天记录
- **特点**：
  - 存储问题和回答
  - 存储推荐的商品ID列表（JSON格式）
- **关联**：
  - 无直接关联，通过 `recommended_goods` 字段关联商品

## 🔄 数据流转关系

### 购物流程
```
用户(device_id) → 购物车(cl_cart) → 创建订单(cl_order) → 订单明细(cl_order_item)
```

### 定制流程
```
用户(device_id) → 创建定制订单(cl_custom_order) → 关联订单(cl_order) → 排队处理
```

### 评价流程
```
用户(device_id) → 评价商品(cl_goods_evaluation) → 更新商品评分(cl_goods.rating)
```

## 📝 字段设计说明

### 状态字段统一规范
- **商品状态**：`0` 上架，`1` 下架
- **订单状态**：`0` 待支付，`1` 已支付，`2` 制作中，`3` 已完成，`4` 已取消
- **定制订单状态**：`0` 待接单，`1` 制作中，`2` 已完成

### 金额字段
- 统一使用 `DECIMAL(10,2)` 类型
- 支持最大 99999999.99 的金额

### 时间字段
- 统一使用 `DATETIME` 类型
- 创建时间、更新时间自动维护

## 🚀 后续扩展建议

1. **用户登录后**
   - 在 `cl_order` 表中添加 `user_id` 字段关联 `sys_user`
   - 在 `cl_cart` 表中添加 `user_id` 字段
   - 保留 `device_id` 字段用于兼容未登录用户

2. **库存管理优化**
   - 可添加 `cl_stock_log` 表记录库存变动日志
   - 可添加 `cl_goods_category` 表实现商品分类

3. **消息通知**
   - 可添加 `cl_message` 表存储消息记录
   - 关联订单状态变更触发通知

4. **数据统计**
   - 可添加 `cl_statistics` 表存储统计数据
   - 或使用视图（VIEW）实时统计

## ⚠️ 注意事项

1. **执行顺序**
   - 先执行主表（`cl_goods`），再执行关联表
   - 外键约束已通过索引实现，无需显式外键

2. **索引优化**
   - 已为常用查询字段添加索引
   - 根据实际查询情况可调整索引

3. **数据备份**
   - 执行前建议备份数据库
   - 生产环境谨慎操作

4. **字符集**
   - 确保数据库使用 `utf8mb4` 字符集
   - 支持emoji和特殊字符
