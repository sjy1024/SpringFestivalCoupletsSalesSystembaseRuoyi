## 🔄 订单状态流转需要手动实现

### 状态流转规则

```
待支付(0) → 已支付(1) → 制作中(2) → 已完成(3)
                ↓
             已取消(4)
```

**状态说明：**
- `0` 待支付：订单刚创建
- `1` 已支付：支付完成（通过支付接口）
- `2` 制作中：管理员开始制作（后台操作）
- `3` 已完成：订单完成
- `4` 已取消：订单被取消

---

## 💻 实现方案

### 方案1：在后台管理页面手动修改（最简单）

**适用场景：** 管理员在后台手动修改订单状态

**实现方式：**
- 代码生成器生成的编辑功能已经可以修改状态
- 在订单列表页面，点击"修改"按钮
- 修改订单状态字段
- 保存即可

**优点：** 简单，不需要额外代码

**缺点：** 需要手动操作，容易出错

### 方案2：添加状态流转按钮（推荐）

#### 2.1 在Controller中添加状态流转方法

在 `ClOrderController.java` 中添加：

```java
/**
 * 修改订单状态
 */
@PreAuthorize("@ss.hasPermi('cl:order:edit')")
@Log(title = "订单", businessType = BusinessType.UPDATE)
@PutMapping("/changeStatus")
public AjaxResult changeStatus(@RequestBody ClOrder clOrder)
{
    // 验证状态流转是否合法
    ClOrder order = clOrderService.selectClOrderByOrderId(clOrder.getOrderId());
    if (order == null) {
        return error("订单不存在");
    }
    
    // 状态流转验证
    String oldStatus = order.getStatus();
    String newStatus = clOrder.getStatus();
    
    // 待支付 → 已支付
    if ("0".equals(oldStatus) && "1".equals(newStatus)) {
        // 允许
    }
    // 已支付 → 制作中
    else if ("1".equals(oldStatus) && "2".equals(newStatus)) {
        // 允许
    }
    // 制作中 → 已完成
    else if ("2".equals(oldStatus) && "3".equals(newStatus)) {
        // 允许
    }
    // 待支付/已支付 → 已取消
    else if (("0".equals(oldStatus) || "1".equals(oldStatus)) && "4".equals(newStatus)) {
        // 允许
    }
    else {
        return error("状态流转不合法：" + oldStatus + " → " + newStatus);
    }
    
    return toAjax(clOrderService.updateClOrder(clOrder));
}
```

#### 2.3 添加状态流转方法

在 `order/index.vue` 的 `methods` 中添加：

```javascript
/** 修改订单状态 */
handleChangeStatus(row, newStatus) {
  const statusMap = {
    '0': '待支付',
    '1': '已支付',
    '2': '制作中',
    '3': '已完成',
    '4': '已取消'
  };
  
  const statusText = statusMap[newStatus];
  this.$modal.confirm('确认将订单状态修改为"' + statusText + '"？').then(() => {
    const order = {
      orderId: row.orderId,
      status: newStatus
    };
    changeStatus(order).then(response => {
      this.$modal.msgSuccess("状态修改成功");
      this.getList();
    });
  }).catch(() => {});
}
```

### 方案3：在Service层实现状态流转逻辑（更规范）

**适用场景：** 需要严格的状态流转控制

**实现方式：**

在 `IClOrderService.java` 中添加：

```java
/**
 * 修改订单状态（带状态流转验证）
 * 
 * @param orderId 订单ID
 * @param newStatus 新状态
 * @return 结果
 */
public int changeOrderStatus(Long orderId, String newStatus);
```

在 `ClOrderServiceImpl.java` 中实现：

```java
@Override
public int changeOrderStatus(Long orderId, String newStatus) {
    ClOrder order = clOrderMapper.selectClOrderByOrderId(orderId);
    if (order == null) {
        throw new ServiceException("订单不存在");
    }
    
    String oldStatus = order.getStatus();
    
    // 状态流转验证
    if (!isValidStatusTransition(oldStatus, newStatus)) {
        throw new ServiceException("状态流转不合法：" + getStatusName(oldStatus) + " → " + getStatusName(newStatus));
    }
    
    order.setStatus(newStatus);
    order.setUpdateTime(DateUtils.getNowDate());
    return clOrderMapper.updateClOrder(order);
}

/**
 * 验证状态流转是否合法
 */
private boolean isValidStatusTransition(String oldStatus, String newStatus) {
    // 待支付 → 已支付
    if ("0".equals(oldStatus) && "1".equals(newStatus)) {
        return true;
    }
    // 已支付 → 制作中
    if ("1".equals(oldStatus) && "2".equals(newStatus)) {
        return true;
    }
    // 制作中 → 已完成
    if ("2".equals(oldStatus) && "3".equals(newStatus)) {
        return true;
    }
    // 待支付/已支付 → 已取消
    if (("0".equals(oldStatus) || "1".equals(oldStatus)) && "4".equals(newStatus)) {
        return true;
    }
    return false;
}

/**
 * 获取状态名称
 */
private String getStatusName(String status) {
    Map<String, String> statusMap = new HashMap<>();
    statusMap.put("0", "待支付");
    statusMap.put("1", "已支付");
    statusMap.put("2", "制作中");
    statusMap.put("3", "已完成");
    statusMap.put("4", "已取消");
    return statusMap.getOrDefault(status, "未知");
}
```

## 🎯 推荐方案

### 对于MVP版本（快速开发）：

**推荐：方案1 + 方案2**

1. **后台管理**：使用方案2，添加状态流转按钮
2. **小程序端**：通过接口自动流转（支付接口自动改为"已支付"）

**优点：**
- 开发快速
- 用户体验好
- 状态流转清晰

### 对于正式版本（规范开发）：

**推荐：方案3**

1. 在Service层实现状态流转逻辑
2. 严格的状态流转验证
3. 更好的代码可维护性
